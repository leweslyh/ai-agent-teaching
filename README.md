# AI智能体互动教学系统（静态版）

**配套《AI智能体科普实践课》（五年级）课程大纲与教案的课堂互动系统。**
让学生通过玩游戏、做实验、和真正的 AI 对话，直观理解智能体四大组件：
**感知器、规划器、记忆器、执行器**，以及大语言模型"大脑"如何把它们协作起来。

> 🚀 **静态版特性**：纯 HTML/CSS/JS，**不需要服务器**，可直接部署到 GitHub Pages / Vercel / Netlify 等免费平台。
>
> 🔑 **API Key 由用户输入**：不硬编码 Key，首次使用时引导用户输入自己的 DeepSeek API Key，保存在浏览器 localStorage。
>
> 🔍 **联网搜索（三级来源，逐级降级）**：**① DeepSeek 服务端联网搜索**——走新版 Responses API（`/responses`）声明 `web_search` 工具，用现有 DeepSeek Key，无需任何第三方搜索服务（⚠️ 该工具只在 `/responses` 上声明，`chat/completions` 不支持；且官方文档说明接口对不支持的内置工具会"静默忽略"，因此系统以"响应里真的出现了 `web_search_call` 或引用来源"作为成功判据，没搜到就自动落到下一级，**绝不把模型自己的话冒充成搜索结果**）；**② 必应 RSS** 多端点 × 多代理并行尝试 + Wikipedia 备用；**③ 大模型已有知识兜底**——如实标注"联网搜索没有成功，这不是刚查到的网页"。课堂演示不中断，来源永远诚实。

## 一、快速开始（三种方式）

### 方式一：一键启动（最推荐）

**（A）前台模式 · `启动.bat`**

双击项目根目录下的 **`启动.bat`**，它会自动完成：检查是否已有服务在运行 → 启动本地服务（默认端口 `8124`）→ 打开默认浏览器。

- **零依赖**：只使用 Windows 自带的 PowerShell，不需要安装 Python / Node
- **前台常驻**：窗口关不掉（服务在里面跑着），**关闭该窗口即停止服务**
- 若 `8124` 已被占用，会自动改用 `8125~8134` 中的空闲端口
- 若服务已在运行，不会重复启动，直接打开浏览器

**（B）后台模式 · `启动_后台.bat`（推荐给脚本 / AI 助手 / 预览截图）**

双击 **`启动_后台.bat`**（等价于 `powershell -File _start_bg.ps1 -Open`）：

- 服务在**独立隐藏进程**里运行，**启动命令秒回**（就绪后打印 `READY http://localhost:8124/index.html`）
- 适合自动化：不会再出现"命令一直卡住不返回"的情况
- 停止服务：运行 `powershell -NoProfile -ExecutionPolicy Bypass -File _stop.ps1`

> ⚠️ **为什么要有后台模式**：`_server.ps1` 内部是"常驻服务循环"，直接在前台运行（包括 `python -m http.server`）会**永久占用终端、永不返回**。在由终端等待命令结束的工具（如 CodeBuddy 等 AI 助手的自动化流程）里，这会表现为"命令卡死、后续步骤全都执行不到"。后台模式把服务与调用方解耦，从根本上避免卡死。

> 📌 **建议始终用这两种方式（或下面方式二）访问**，而不要直接双击 `index.html`。
> 直接用 `file://` 打开时，页面 Origin 为 `null`，浏览器会拒绝跨域请求，且不把本地文件视为安全上下文——结果是**云端语音识别、云端图片识别、AI 对话会失效，麦克风权限也不稳定**。用 `http://localhost` 访问则被视为可信来源，所有功能正常。

### 方式二：手动启动本地服务器（需 Python 3）

需要 Python 3（仅用于启动静态文件服务器，不需要任何第三方包）：

```bash
# 进入项目目录
cd AI智能体互动教学系统_静态版

# 启动静态文件服务器（端口 8124）
python -m http.server 8124

# 浏览器访问
# 打开 http://localhost:8124
```

> ⚠️ `python -m http.server` 与 `_server.ps1` 一样是**前台常驻**进程，会一直占用终端、命令不返回。若用于自动化 / 脚本 / AI 助手，请改用 `_start_bg.ps1`（后台模式，见方式一·B）。

### 方式三：部署到免费平台（推荐正式使用）

见下方「部署指南」章节，可部署到 GitHub Pages / Vercel / Netlify，完全免费，随时随地访问。

## 二、首次使用：配置 API Key

系统共用到**两个相互独立的 API Key**，都可以留空——留空只会降级，不影响知识讲解、游戏和小测验。

### DeepSeek API Key（智能体对话用）

1. 打开页面后，会自动弹出「欢迎使用」引导窗口
2. 按照提示，到 [DeepSeek 开放平台](https://platform.deepseek.com/) 注册并创建 API Key
3. 将 Key（`sk-` 开头）粘贴到输入框，点击「保存并开始使用」
4. 如果暂时没有 Key，可以点击「稍后再说」，知识讲解、游戏、小测验等功能**不需要 Key** 也能使用
5. 之后可随时点击右上角齿轮「设置」按钮重新填写 API Key（模型由系统统一配置为 `deepseek-v4-flash`，不需也不支持在页面上切换）

### 硅基流动 API Key（语音识别 + 图片识别 + 思维链实验共用）

「感知器」实验室的语音识别与图片识别、「规划器」实验室的**思维链（CoT）实验**都需要云端算力，因此需要**额外的密钥**。

**三者共用同一个 Key，只需申请一次**：

| 功能 | 用途 | 默认模型 |
| --- | --- | --- |
| 语音识别（ASR） | 麦克风说话 → 转成文字 | `FunAudioLLM/SenseVoiceSmall` |
| 图片识别（OCR） | 上传图片 → 提取图中文字 | `Qwen/Qwen3-VL-8B-Instruct` |
| 思维链实验（CoT） | 「直接问」vs「一步一步想」的小模型对照组 | `Qwen/Qwen2.5-7B-Instruct`（7B 小模型） |

> 💡 **为什么思维链实验要用 7B 小模型**：小模型"跳步就容易错"，一步步想的效果差距最明显；没配这个 Key 时，实验会自动改用 DeepSeek 大模型对比（效果差距会小一些）。

1. 打开 [硅基流动开放平台](https://cloud.siliconflow.cn/)，注册并登录（新用户赠送免费额度）
2. 左侧菜单进入「API 密钥」→ 点「新建密钥」
3. 复制 `sk-` 开头的那串字符
4. 回到本系统 → 右上角齿轮「设置」→ 粘贴到「**云端能力密钥 · 硅基流动 SiliconFlow**」输入框 → 点「保存」
5. 回到「感知器」实验室，点页面顶部「**刷新状态**」，状态标签会从「降级可用」变为「**云端已就绪**」；保存设置后「规划器」实验室的模型条也会同步（CoT 实验改为 7B 小模型对照）

**不配置也能上课**——系统会自动降级，知识内容完整不受影响：

| 能力 | ① 云端（已配 Key） | ② 降级（未配 Key） | ③ 断网 |
| --- | --- | --- | --- |
| 语音识别 | 硅基流动 SenseVoice | 浏览器内置识别（**Edge 浏览器可直接用**） | 示例讲解 |
| 图片识别 | 硅基流动视觉大模型 | 本地 Tesseract 引擎（首次需联网下载语言包） | 示例讲解 |
| 思维链实验 | 7B 小模型 vs DeepSeek 大模型对比（差距最明显） | DeepSeek 大模型自己和自己比（差距会小） | 内置示例演示 |

> 🔒 **安全说明**：两个 Key 都只保存在**本机浏览器**（localStorage），不会上传到任何服务器。浏览器直接调用 DeepSeek 与硅基流动的官方 API（`api.deepseek.com`、`api.siliconflow.cn`），不经过任何中间服务器。

## 三、部署指南

### 部署到 GitHub Pages（免费，推荐）

1. 注册 [GitHub](https://github.com/) 账号
2. 创建一个新仓库（Repository），名字比如 `agent-teaching`
3. 将本项目所有文件上传到仓库（可以直接网页拖拽上传，或用 Git）
4. 进入仓库 **Settings** → **Pages**
5. Source 选择 `Deploy from a branch`，Branch 选 `main` / `root`，点击 Save
6. 等待 1-2 分钟，就能通过 `https://你的用户名.github.io/agent-teaching/` 访问了！

### 部署到 Vercel（免费，国内访问较快）

1. 注册 [Vercel](https://vercel.com/) 账号（可用 GitHub 登录）
2. 点击「Add New...」→「Project」
3. 导入你的 GitHub 仓库，或直接上传项目文件夹
4. Framework Preset 选「Other」，Build Command 留空，Output Directory 留空（或填 `.`）
5. 点击「Deploy」，等待部署完成
6. 会得到一个 `https://xxx.vercel.app` 的网址，随时随地访问

### 部署到 Netlify（免费）

1. 注册 [Netlify](https://www.netlify.com/) 账号
2. 点击「Add new site」→「Deploy manually」
3. 将项目文件夹拖拽到上传区域
4. 等待部署完成，得到 `https://xxx.netlify.app` 网址

### 部署到 Gitee Pages（国内访问快，需要实名认证）

1. 注册 [Gitee](https://gitee.com/) 账号并完成实名认证
2. 创建新仓库，上传项目文件
3. 进入仓库「服务」→「Gitee Pages」
4. 选择分支，点击「启动」
5. 得到 `https://你的用户名.gitee.io/仓库名/` 网址

## 五、课堂建议的使用顺序

0. **先停 10 秒在封面**：让学生看清系统由**七个实验室 + 一个作品集**组成、各自玩什么，点「开始探索 · 起源实验室」进入主线；任何时候点顶栏左上角标题即可回到封面。
1. **先看起源实验室**（L01+L02）：从 AI 发展史和大模型原理入手，玩图灵测试体验站、看职业演变四阶段、讨论 AI 伦理和人类该如何面对 AI；再认识身边的智能体（6大领域/产品全景/四代进化），理解推荐算法和信息茧房，最后思考"AI 有意识吗"。
2. **再看架构实验室**（L03+L04）：整体认识四组件与大脑，玩总装图拼装（点击式）、组件抢答；再用"拆解四问"分析智能客服示范，切换 5 个真实案例库（含腾讯CodeBuddy深度拆解），看五种 Agent 产品对比。
3. **依次进四个实验室**（L05–L12）：玩一个组件，点一个组件，攒知识。
4. **进智能体实验室**（L13）：先看**导入卡**对上账（这一课把前面四个实验室合起来了）；学生提问，全班盯着"工作台"看五步点亮；做**上下文实验**把四条消息拼出来，点"拆开看看"对照真实请求；可以现场关掉"记忆器"或"执行器"，让学生自己发现"少了它就不行"；再做**"体检"**和**"读轨迹找故障"**两个实验——知道怎么判断"它到底变好没有""错在哪一环"。
5. **最后进「作品展示」**（作品集，L14–L16 展示环节的线上版）：带学生看两个"真作品"——**班级小助手**与**出行小管家**：先读它们的**制作过程**（六步：定目标 → 配感知器 → 写系统提示词 → 装工具 → 接记忆 → 联调测试），再对照**四大组件**看每个作品是怎么被搭起来的，然后打开它们的**岗位说明书**看看真实提示词长什么样（学生问"它怎么不会答天气"，答案就在这份提示词的"边界"那一段里），最后**现场和它们对话**（点"试试这样问"或自己提问，右侧「它的内部工作台」会随对话点亮总装图——大脑居中、四组件环绕，连线跟着信息的方向亮——并逐步记下轨迹：状态牌 + 轮次/工具/用时的统计胶囊 + "本轮轨迹"里连工具调用与返回结果都照实写下）；最后读**对比小结**：两个作品用的是**同一套四组件**，差别只在"记忆内容"与"工具配置"——顺势把全课收口到"你也能照着搭一个属于自己的智能体"。
6. 可以结合教案里的**"卡住三步走"**课堂常规：先自己读并复述、再清晰提问、最后求助老师/同伴。

## 七、三个全站通用引擎（学生不感知，但每个板块都在用）

这三层是把八个板块"对齐"的关键，也是最近一轮重构的成果。

### 7.1 `quiz-flow.js`——「单题闯关」答题引擎（`AgentLab.Quiz`）

把散落各板块的选择题（小测验 / 游戏题 / 判断题 / 进阶课堂里的迷你测验）统一成一种流程：

1. **一次只出一题**，答完才出下一题，配进度条与题号（如「第 3/10 题」）；
2. **答对**：即时判定 + 加星 + 庆祝动效 + 讲解，20 秒后自动进入下一题（也可点「下一题 →」立刻继续）；
3. **答错第一次**：只抖动提示"再想想"，**不揭答案**，并锁掉已选错的选项；
4. **答错第二次**：标出正确项并讲解，本题不加星，同时记进"待回顾"清单；
5. **全部答完**：给得分条、分级点评（满分 / 非常棒 / 做得不错 / 别急）、针对性建议、**需要回顾的题目清单**（标注"第二次才选对"还是"两次都没选对"）与「再来一次」。

题面数据在七个板块里原本写法各不相同，引擎会自动兼容 `q/question`、`opts/options`、`ans/correct`（支持选项序号、选项文案、布尔判断、多个正确项）等历史字段，**不必改数据**。

### 7.2 `adv-classroom.js`——「进阶原理互动课堂」共享引擎（`AgentLab.Adv`）

七个板块的"进阶原理互动课堂"共用同一套实现，板块只需要写**内容数据**：

- **结构**：左侧概念导航 + 右侧讲解面板（**一句话 / 打个比方 / 真实系统 / 动手互动 / 自检一问 / 一键跳回对应实验**）；
- **内置 18 种可复用交互类型**（`AgentLab.Adv.types`）：`modality`（多按钮切换 + 工序链）、`switchboard`（观察通道开关 + 动作依赖判定）、`composer`（消息池点选 → 实时生成真实请求 JSON）、`calculator`（Token 计价器）、`vectorMap`（向量小地图 + 最近邻 Top3；可选传 `threshold` 启用「相关度门槛」——最像的一条记 100 分，没到门槛的邻居灰掉、不进入上下文）、`decider`（答两问给结论）、`sandbox`（污染内容沙盒 + 防护开关；除提示注入外，记忆器还用它做"留着过期信息会怎样 + 到期自动清理开关"）、`squeezer`（上下文窗口挤压模拟器）、`pipeline`（多阶段管线 + 逐步揭示）、`sorter`（步骤排序 + 并行组）、`tuner`（滑条调参看指标变化；「拖一圈再判断」的判断题在学生真正拖动过滑条后才出现）、`picker`（多选判定）、`annotator`（**在真实材料上点选**——网页正文 / 调用日志 / 用户原话，先认出目标再逐条判定，比在一串按钮里挑更接近真实任务）、`matcher`（左右两列配对，右侧可被多条共用，适合「工具↔五分类」「场景↔规划范式」「记忆实例↔记忆类型」「信息↔存储格式」）、`budget`（上下文预算分配器：自己决定静态前缀 / 检索片段 / 轨迹 / 当前问题各占多少，实时看总量与溢出时谁先被挤掉）、`apiCall`（**一次调用的「请求 ↔ 响应」左右对照**：左边是真正发出去的请求行 / 请求头（含鉴权）/ 请求体，右边是模型回来的 `content` / `tool_calls` / SSE 片段；每种模式可顺带改写请求体——学生能看见"参数只改一处，回来的东西完全不一样"；**现已在两处落地**：感知器「怎么调用大模型」（普通回答 / 要求调工具 / 流式返回三种形态）、执行器 Function Calling 卡（没声明工具 / 声明了工具 / 参数类型写错三种形态）——同一套视觉语言，两个不同场景）、`race`（**双轨推进对比**：同一件事的两种做法并排走，点「走一步」两栏同时推进一格，先走完的停住并显示结局，两栏都走完才亮出对比结论 + 判断题——规划器用它做"有清单 vs 无清单""清单计划 vs 一段话计划"，执行器用它做"带幂等键重试 vs 直接重发"，记忆器用它做"只查一次 vs 多查几轮"）、`ranker`（**打分排名：谁会被想起来**——每条记忆带"记于几天前 / 重要性"，先猜一条再「揭开打分」看按分数（相关性 × 时间衰减 ×（0.8+重要性×0.4））排序的榜单与分数条，可切换问题、拖"时间衰减半衰期"滑条看排序怎么变——记忆器专用）；
- **同一个话题换一种交互动手方式**（本次优化重点）：**"上下文窗口"全课只用一个比方——"书桌"**（原先感知器叫"白板"、规划器叫"工作手册"、记忆器叫"书桌"，三套比喻互相打架）。统一之后三页各管一件事，且都在正文里写明了分工：**感知器**问"哪些东西值得放上桌"（`squeezer`）、**规划器**问"桌上的草稿纸为什么越堆越多、满了先丢什么"（`squeezer`）、**记忆器**问"桌面怎么分配"（`budget`）——同一个比方，三个不同动作，学生不会连听三遍同一个结论；向量空间在感知器（`vectorMap`：语义相近）与记忆器（`vectorMap` + 相关度门槛：检索命中与划线取前几名）各有侧重；
- **通用「达标检查表」**（`checklistHTML`）：把"两种问法感觉差不多"变成明确的 **几比几**，并自动生成一句大白话结论；
- **有 Key 走真实模型、无 Key 走内置示例**（`askOrDemo`）：两侧并发提问，并对"只返回空内容"的那一侧自动补一次重试，避免界面卡在"正在提问……"。

### 7.3 `reveal.js`——苹果风滚动进场动画（`AgentLab.Reveal`）

- 只作用于结构性大块（卡片 / 页头 / 分隔条 / 主视觉），**不碰正文与小组件**；
- 共享单个 `IntersectionObserver`，进场后即 `unobserve`；
- 栏目切换时自动重新扫描（`section` 默认 `display:none`，隐藏元素没有盒子）；
- **失败永不见白屏**：只有脚本成功执行并给 `<html>` 加上 `.js-reveal` 后元素才隐藏；JS 失败、不支持 `IntersectionObserver`、或用户开启「减少动态效果」时一概不加该类，元素保持默认可见。

- **组件开关**：在"智能体实验室"右侧工作台现场开关感知/规划/记忆/执行，观察本领变化。

## 十、说明与安全提示

- **API Key 由用户输入**：静态版不硬编码 API Key，首次使用时引导用户输入自己的 DeepSeek API Key，保存在**本机浏览器**（localStorage）。浏览器直接调用 DeepSeek 官方 API（`api.deepseek.com`），不经过任何中间服务器。
- **Key 安全建议**：由于 Key 存储在浏览器中，建议只在信任的设备上使用；给 DeepSeek 账户设置消费上限；定期更换 Key。不要把包含他人 Key 的浏览器配置对外公开。
- **云端能力密钥（语音识别 / 图片识别 / 思维链实验）**：「感知器」实验室的语音识别与图片识别、「规划器」实验室的思维链（CoT）对照实验，会调用硅基流动接口，**三者共用同一个 Key**，与 DeepSeek Key **相互独立**，均可留空。留空时会自动降级：语音改用浏览器内置识别（Edge 可用），图片改用本地 Tesseract 引擎，思维链实验改用 DeepSeek 大模型做对照；若都不可用（例如断网），实验会切换为**示例演示**，知识内容完整、课堂不中断。密钥同样只保存在本机浏览器，浏览器直连 `api.siliconflow.cn`。
  - 本地 Tesseract 引擎的脚本**不在页面加载时引入**，而是在你真正点「开始识别」时才按需加载，并依次尝试 jsDelivr / unpkg / cdnjs 三个 CDN——这样即使某个 CDN 不可达，页面也不会报资源加载错误，识别会自动换源或降级为示例演示。
- **天气是真实数据**：天气工具联网调用 [Open-Meteo](https://open-meteo.com/)（免费、无需 Key、支持跨域）：先按城市名查到经纬度，再取未来 8 天的真实温度/降水概率/风力，并据此给出穿衣建议。断网或查询失败时会如实告诉学生"没有查到真实天气"，**绝不编造数字**。城市名仅作为查询参数发送给 Open-Meteo，不涉及任何隐私信息。
- **联网搜索依赖网络，三级来源逐级降级**：
  - **① DeepSeek 服务端联网搜索（预留）**：走新版 Responses 接口（`https://api.deepseek.com/responses`）声明 `web_search` 工具，用现有 DeepSeek Key。
    > ❌ **2026-10 实测（Key 有效、HTTP 200）**：`/responses` 会**静默忽略** `web_search` 工具——响应里没有任何 `web_search_call` 或引用，模型甚至在思维链里明说"我没有联网工具"；`/chat/completions` 则直接 **422**（`tools[0].type: unknown variant web_search`）。社区 2026-08 的"实测可用"文章与当前接口行为不符。
    > 因此系统以"响应里真出现 `web_search_call` 或引用来源"为成功判据：没搜到就自动落到 ②，并把"该接口忽略此工具"记入本机（localStorage），**7 天内不再白等这 18 秒**；想提前重试可清除该记录或在 `js/config.js` 把 `deepseekWebSearch` 设为 `false`。DeepSeek 侧若日后放开，无需改代码即可自动启用。

  - **③ 大模型已有知识兜底**：①② 都失败且已配置 Key 时，自动改用大模型已有的知识回答，并**如实标注"联网搜索没有成功，这不是刚查到的网页"**；未配置 Key 时会明确提示原因。
